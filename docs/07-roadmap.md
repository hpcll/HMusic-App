> 每个里程碑 = 明确产出 + 可勾选验收项。完成后把勾打上并在 00-overview 更新状态。

## M0 · 骨架（预计 0.5-1 天）

产出：Tauri 窗口跑起来，加载现有 web/，能连本地 Server。

- [ ] `scripts/sync-web.sh` 可重复执行，src/ 与 HMusic-Server/web 一致（native/ 不被删）
- [ ] `cargo tauri dev` 打开 1200×800 窗口，UI 渲染与浏览器版无肉眼差异（深浅色都试）
- [ ] api.js serverBase 改造合入 HMusic-Server（网页端回归：浏览器打开 /app/ 一切照旧）
- [ ] 客户端首屏「连接服务器」→ 填 `http://127.0.0.1:8090` 探活 → 登录成功进播放页

## M1 · 核心闭环（1-2 天）

产出：听歌主链路全通。

- [ ] 搜索 → 播放（本机播放出声！streamUrl 的 serverBase 改写生效）
- [ ] 播放页：进度推进不回跳、拖 seek、音量、上下曲、收藏、歌词同步滚动
- [ ] 队列：点播/删除/切模式/清空；播完自动下一曲（ended 上报链路）
- [ ] 切到音箱设备播放也正常（远程遥控模式）
- [ ] 退出重开：token 记住、播放状态恢复显示

## 风险登记簿

| 风险 | 影响 | 对策 |
|---|---|---|
| 自研移动音频插件工作量超预期 | M4 排期 | 先 iOS 后 Android 分两步交付；开发期间以「前台播放 + 遥控器」临时过渡（仅过渡，不是终态） |
| WKWebView/WebView2 对 color-mix/mask 等新 CSS 支持差异 | 视觉偏差 | M0 就双平台肉眼验收；有问题给降级 CSS |
| qrcode.js 在 webview 的 window 注入时机 | 扫码登录 | 已有缺失降级提示；必要时改 ESM 引入 |
| 用户填错服务器地址 | 首用挫败 | 探活失败给明确文案 + 常见地址示例 |
| 双仓库前端漂移 | 维护成本 | 铁律：UI 只改 HMusic-Server/web，sync 单向流 |

## 1. 目标与已有事实

HMusic 的主要路径是：
连接自建 Server → 搜索/榜单找歌 → 保存到服务器曲库/歌单 → 选择本机或小爱音箱 → 播放/队列/歌词。

这次优化让曲库、播放目标和常用控制更容易到达，改善宽屏空间使用，同时保留墨色、衬线标题和少量青绿的品牌语言。

已确认的当前问题：

| 编号 | 当前行为 | 本轮目标 |
| --- | --- | --- |
| UI-01 | 手机四项为榜单/歌单/统计/设置，NAS 曲库在歌单内部 | 手机改为找歌/曲库/设置，曲库直接切换歌单与 NAS 歌曲，统计仍可到达 |

## 2. 实施边界

本轮实施 UI-01 至 UI-10 中能由现有客户端能力完成的部分：

- 保留七条 StatefulShell branch 的顺序和已有路由路径，调整入口与展示层级。
- 沿用唯一 HMusicAudioHandler、PlaybackCoordinator、PlayerViewModel、Server 状态和本机/远端进度来源。
- 不新增音频后端，不改本机后台连播、URL 签名、鉴权、队列写入和音箱音量契约。
- 不新增第三方依赖，不重启已回退的 Android 透镜/折射实验，不恢复 WebView/Tauri。
- 不实现托盘、自动升级、Spotify 接入、多客户端仲裁等独立功能。
- 本轮歌单使用有区分度的确定性封面占位；真实歌单/专辑摘要封面在第 8 节另列数据任务。
  不对每张卡发详情请求，不声称已有封面 API。
- 队列仍保留完整页面。常驻播放条增加直接入口；右侧队列抽屉作为后续增强，不作为本轮完成条件。
- 当前未提交改动作为基线保留。不得 reset、checkout 覆盖、创建分支、commit 或 push。
- 搜索页已有参数行混入“继续”的语法错误，只做最小修正并记录，不把其他人的改动整段重写。

## 3. 交互与页面规格

### 3.1 手机导航、曲库与返回

| 显示入口 | 保留 branch | 保留 native id | 内容 |
| --- | --- | --- | --- |
| 找歌 | 4 | charts | 搜索入口、家庭榜、各来源榜单 |
| 曲库 | 3 | playlists | 歌单 / NAS 歌曲根分段；后者继续支持全部/歌手/专辑/文件夹 |
| 设置 | 6 | settings | 账号、设备、音源、播放、服务器、安全、更新 |

规则：

1. /charts、/playlists 等路径不改名，深链和历史路由继续有效。
2. 找歌页标题用“找歌”；桌面独立榜单入口可继续叫“榜单”，独立搜索路径保留。
3. 曲库根页提供“歌单 / NAS 歌曲”分段，直接看见两类内容，不再先进入歌单再找 NAS 卡片。
4. 歌单态保留创建、导入、详情、播放、删除确认；NAS 态保留分组、搜索、分页、上传、扫描。
5. NAS 根分段选择本身不算二级页面。返回先关闭歌单详情或 NAS 分组，再按壳层规则回找歌。
6. “听歌统计”从曲库可进入；/stats 属于曲库父入口，手机选中曲库，返回回曲库。
7. 输入或分组状态在旋转、调整窗口、根分段切换时尽量保留；不得因布局切换重建全部业务状态。
8. 空态、错误、导入结果和上传进度继续使用已有就地反馈，不恢复全局 toast。
9. /search、/player、/queue 全屏页面保留。宽屏进入对应 tabPath，手机 push；缩放不丢失正在看的内容。

### 3.2 中屏与桌面导航

统一使用 shared/layout/shell_metrics.dart 中的 API：

```dart
enum ShellNavigationMode { bottom, rail, sidebar }

ShellNavigationMode shellNavigationModeForWidth(double viewportWidth);
bool usesBottomNavigation(double viewportWidth);
double shellNavigationWidth(double viewportWidth);
double mobileMiniPlayerHeight(TextScaler textScaler);
bool canMinimizeBottomChrome({
  required double viewportWidth,
  required TextScaler textScaler,
});
```

| 视口宽度（逻辑像素） | 外壳 |
| --- | --- |
| <700 | 手机底栏 |
| 700–1023 | 80 宽 rail，图标有 tooltip/语义，当前项明确 |
| ≥1024 | 232 宽分组侧栏 |

- 路由打开方式统一用 usesBottomNavigation；播放器、设置、列表自身分栏使用 LayoutBuilder 的内容宽度。
- 桌面导航按浏览、音乐库/回顾、播放、设置组织；保留搜索、榜单、曲库、统计、正在播放、队列、设置全部能力。
- rail 的目标与完整侧栏一致，键盘可到达，不能靠无标签图标猜功能。
- 额外标题栏留白按平台取值：macOS 使用现有隐藏标题栏需要的 28；Windows/Linux/iPad 不统一加 28。
- 恢复适合桌面的滚动条；避免给无控制器的嵌套列表造成重复/冲突的 scrollbar。
- 设置菜单宽为 `240 * max(1, scale(14)/14)`，再加间距 32、正文至少 480 和两侧 32；
  基础字时需 784、2 倍字时需 1024 内容宽，否则使用菜单→详情单页。
  切换布局保留已选 section 和未提交表单输入；宽布局默认展示的首项也要记录选择，
  避免缩窄时回到菜单而卸载正在填写的表单。

### 3.3 常驻播放控制

**桌面播放条**

- 与手机 mini 分成专门展示组件，共用现有播放状态和动作，不复制播放器状态机。
- 内容足够宽时三段：曲目/收藏；上一首/播放暂停/下一首与进度；当前设备/音量/队列。
- 900×600 窗口仍要显示设备和核心操作。空间不足时允许两行排布，进度/音量不得挤成不可操作的短线。
- 为有播放条的内容保留真实高度；完整播放器页按现有规则不重复显示播放条。
- 无曲目、加载、暂停、错误、不可 seek 状态有明确展示；未知时长禁用 seek，时间使用现有格式。
- 进度复用 playbackPositionOf / livePosition，远端进度继续使用已有投影。
- 本机音量连续更新本机播放器与偏好；远端拖动只预览，松手一次提交，设备切换后 slider 不串值。
- 队列按钮进入当前宽度适用的既有队列页面；不复制队列数据。

**手机与 iOS native mini**

统一三行：曲名 14、歌手 12、输出名称 12；行高 1.25，行间各 2，上下 padding 总计 16。

```text
height = max(72, ceil(20 + (scale(14) + 2 * scale(12)) * 1.25))
1× ≈ 72，1.5× ≈ 92，2× ≈ 115
```

- Flutter 与 Swift 消费同一高度和缩放后的字号；不使用缩放限制来隐藏溢出。
- 输出名称独立可点，打开现有设备选择；点曲目区域进入完整播放器，两者 intent 不能串触发。
- 所有独立图标操作命中至少 44×44；长歌名/设备名省略，语义读出完整名称与目标。
- 文字比例 >1.2，或收缩后 mini 宽不足 280 时保持展开，避免大字模式被压进圆钮旁。
- Flutter 外壳包络、最小化圆钮几何、native mini 与底部 inset 均使用上述计算结果。
- 大字同时验证 dock 标签高度，必要时增加 dock 自身包络。
- Native 消息最小增量：NowPlaying.outputLabel；openOutputPicker intent；
  updateLayout 增加 mini 高度、缩放后的字号、allowMinimize。
- 原生层只渲染/发送 intent，不读取 Server、不保存业务状态；同曲切设备也必须刷新输出文案。
- iPad 在使用 rail/sidebar 时隐藏原生 dock/mini，单纯旋转也要触发显隐及 inset 重算。
- 收缩后展开主动回报新 inset，不等待系统 tab bar frame 碰巧变化。
- 保留现有实际启用的 UIKit 系统 dock，不启用残留不可达的 SwiftUI 自绘 dock。

### 3.4 完整播放器

- 将超过规模门槛的 player_page 拆成布局与复用绑定组件，Page 负责选择形态。
- 使用实际内容区宽高选择双栏、竖向或短横屏结构；封面是可缩内容，控制区必须可达。
- 844×390 与 360×640、文字 1/1.5/2 都不出现 RenderFlex 溢出。
- 矮屏必要时滚动；正常手机仍优先单屏。不得用无限高度包 Expanded 的方式产生新异常。
- 保留封面滑动切歌、歌词入口/同步、播放模式、收藏、设备状态、音量和已有快捷键。
- 本轮不将完整播放页面重写为原生，不改变音频生命周期。

### 3.5 音乐内容与列表

**曲库/歌单**

- 在 app 组合层拼接歌单与 NAS 功能；feature 提供小的可嵌入视图/回调，避免新增跨 feature VM 调用。
- 根分段有清楚选中态，页头主要操作随分段变化；避免两套标题/返回栏重复堆叠。
- 根分段使用墨色/灰阶，不铺大块青绿。NAS 工具、分类、搜索与列表在同一纵向滚动区；
  小屏大字和短横屏下，搜索及曲目动作须能滚到播放条上方，不能仅以无 RenderFlex 异常验收。
- 歌单卡增加稳定、可辨认的占位封面：基于 id/name 的稳定映射、字形/几何/色调，不依赖随机数。
- 同一歌单每次展示一致；浅深色可读；空名称有合理兜底。
- 卡片主要动作是打开/播放；删除放“更多”菜单，使用明确“删除歌单”文案，保留二次确认。
- 封面占位不冒充专辑照片。未来 cover 字段存在时可替换，当前不额外请求详情。

**桌面曲目列表**

- 复用一个真正被搜索与曲库共同使用的展示组件，输入现有 track 和动作回调。
- 宽度充足时按歌曲、歌手/专辑、时长、必要来源分列，末端动作固定宽度，主列得到主要空间。
- 中屏减少列数，手机保留封面+歌名+次要信息两行；避免依赖整机宽度判断。
- 不为填满表格虚构时长/音源，不存在的字段使用短占位或不显示。
- 歌曲操作继续调用原 VM；下载/加队列的确认与错误保持就地反馈。
- 搜索结果内容区域采用稳定内容面板，玻璃保留在搜索/导航等控制层。
- 命中区与 tooltip 延续现有规范；输入框聚焦时不触发播放快捷键。

**榜单**

- 手机主推卡降低横幅支配感，方封面保留可辨认比例，标题/来源成为稳定文字区。
- Top3 歌名与歌手分层，避免两者争抢同一行。卡高随文本缩放或展示规格调整。
- 桌面使用完整网格；手机保留可横滑的卡带，所有来源仍可沿页面纵向到达。
- 保留家庭榜、网易云、QQ、Apple 来源，保留 Apple 搜索匹配逻辑和当前播放指示。
- 不把全部卡片玻璃化，不引入新封面网络请求。

### 3.6 平台能力与文案

- 集中定义客户端 supportsLocalPlayback，Android/iOS/macOS 为真，Windows/Linux 为假；
  不将 server system/info 未完备的 capabilities 作为隐藏内容功能的依据。
- 本机选项在不支持的平台上不可提交选择，并给出“此平台暂不支持本机播放，请选择音箱”等简短原因。
- 本机音源装载若会因共享 Server 状态触发，也应有最小平台门禁；不得另造 remote handler。
- 锁定依赖的 audio_service 在 Win/Linux 有 NoOpAudioService；不能仅因无注册插件就断言遥控初始化崩溃。
- 设备列表主要展示名字、在线/离线、当前输出；browser/L06A 等内部型号不作为主要说明。
- 统一使用“服务器下载”；动作说明“保存到已连接的服务器”，不承诺手机离线可用。
- 保留设备刷新/探测、失败反馈、下载列表/重试/删除；不得把这些功能随着入口调整丢掉。

## 4. 执行分工与文件所有权

所有 agent 在同一工作树工作；每块只修改自己的文件。共享协议先按本文确定，缺少接口先发消息，
不要越界改别人的文件。完成时报告具体行为、文件、测试、剩余风险。不要各自更新路线图，
不要同时跑全仓 dart format 或完整测试；主 agent 统一收口。

| 执行包 | 所有者 | 主要文件范围 |
| --- | --- | --- |
| A 外壳与原生导航 | shell_ui | lib/app/shell、shared/layout、core/platform_shell、ios/Runner 原生壳、app_router 路由接线、hmusic_app 滚动行为、SettingsPage 响应式 |
| B 播放控制与能力 | playback_ui | features/player；新增 core/platform 客户端能力小模块；必要的 core/audio 本机装载门禁；settings 设备 UI；对应测试 |
| C 音乐内容 | content_ui | features/playlists/library/charts/search；app 层曲库组合页；共享曲目行/占位视觉组件；settings 下载文案；对应测试 |
| D 集成与最终审查 | 主 agent | 本方案、设计文档同步、roadmap、审查记录、跨块测试与截图、发现问题后反馈执行 agent 修复 |

协作约定：

1. A 实现第 3.2 节公共布局 API，并告知 B/C 可用时间。
2. B 的 mobile mini 排版严格使用第 3.3 节字号/高度；A 负责 Flutter 包络与 native 对应关系。
3. B 自行定义 desktop 播放条高度计算入口并告知 A，A 用相同结果预留内容底部。
4. C 提供曲库组合页类/路由接线方式；A 只改既有 branch 的 builder，不重排 branch。
5. /stats 手机父入口固定为曲库；A 负责壳选中与返回，C 提供入口。
6. iOS 新增 Swift 文件必须加入 Xcode Sources；按职责拆分当前超长文件，避免扩大巨型文件。
7. 不修改用户的 .claude-handoff-night.md、.zcode 及其他与任务无关的内容。

## 5. 实施顺序

1. 主 agent 保存当前工作树差异基线，落盘本方案。
2. A 先提供共享布局 API；B/C 可并行拆分自身组件和添加有意义的回归用例。
3. A 完成三档导航/native 同步；B 完成播放条/横屏/能力；C 完成曲库/卡片/列表/文案。
4. 主 agent 检查跨块接线、既有用户改动是否保留，按场景执行 format/analyze/test。
5. 主 agent 运行当前组件布局预览、检查截图，将缺陷反馈对应 agent；修正后只重跑受影响检查。
6. 汇总最终审查。真实设备未完成的条目保持未验收，不凭 widget 渲染勾选。
7. 不发布、不提交；交付工作区中的已审查改动、详细方案与验证记录。
